# P8 PR #17 — Backend Gateway Foundation

## Decision

The Gateway is a separately deployable FastAPI service under `backend/`. The React/Vite Prompt Studio remains a static-capable local-first application. The browser must never receive provider credentials.

P8 is split deliberately:
- PR #17: HTTP service foundation, versioned API boundary, health endpoint, request correlation, CORS configuration, error envelope, and Python CI.
- PR #18: provider registry/manager and encrypted secret storage.
- PR #19: Gemini/Nano Banana adapter and provider execution.
- PR #20: image generation/editing UI connected to the Engine.

## Runtime

- Python 3.11+
- FastAPI + Pydantic Settings
- ASGI server: Uvicorn
- Tests: pytest + FastAPI TestClient/httpx

Install and run:

```bash
cd backend
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest
```

## API v1 foundation

| Method | Path | Purpose | Auth |
|---|---|---|---|
| GET | `/healthz` | Liveness/service metadata | Public |
| GET | `/api/v1/healthz` | Versioned health alias | Public |

OpenAPI is served by FastAPI at `/docs` in development. Business endpoints are intentionally not exposed in PR #17; they require authentication and provider/secret boundaries from later P8 PRs.

### Response conventions

Success health response:

```json
{
  "status": "ok",
  "service": "piecs-gateway",
  "api_version": "v1"
}
```

Validation error envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request payload is invalid.",
    "details": []
  }
}
```

Every response passing through the application middleware receives a server-generated `X-Request-ID`. Client-supplied values are not trusted as correlation identifiers.

## Configuration

Environment variables use the `PIECS_` prefix:
- `PIECS_APP_ENV`: `development` (default) or `production`.
- `PIECS_SERVICE_NAME`: service identifier.
- `PIECS_API_VERSION`: API version label.
- `PIECS_CORS_ORIGINS`: comma-separated exact origins; defaults to local Vite origins.

Wildcard CORS is rejected in production. Production deployments must configure explicit HTTPS origins and terminate TLS at a trusted ingress/proxy.

## Security boundaries

- No provider API keys, secrets, or credentials are accepted or returned in PR #17.
- Never put secrets in Vite `VITE_*` variables, browser storage, prompt packages, workflow snapshots, logs, or API responses.
- Provider credentials will be stored server-side by PR #18 using an authenticated, encrypted-at-rest vault; encryption key material must be injected from deployment secrets/KMS, never committed.
- Business routes must require authentication before provider or asset operations are added.
- CORS is not authentication. It is only a browser-origin policy.
- Do not log authorization headers, request bodies containing credentials, or provider responses that may echo secrets.
- Request IDs are generated by the server to avoid log-forgery via caller-controlled identifiers.

## Non-goals

No provider SDK, provider manager, API-key vault, image upload, image generation, workflow orchestration over the network, billing, tenant model, or cloud asset storage is included in this PR.

## Acceptance criteria

- Gateway starts independently of the frontend.
- Health endpoint returns service metadata.
- Server emits a generated request ID.
- Production configuration rejects wildcard CORS.
- Python tests run in GitHub Actions alongside existing frontend checks.
- Existing Prompt Studio, IndexedDB, and local Demo Adapter behavior remain unchanged.
